PART 2 — RUNTIME CRASH: "SUPABASE_URL missing from build settings"
=====================================================================
After the build fix, the user got a runtime fatal error in Config.swift when actually running
the app. Root-caused to two separate, compounding bugs:

  1. .xcconfig files treat "//" as a start-of-line COMMENT MARKER. The line
     `SUPABASE_URL = https://mimqecwisgzpdbeygcyj.supabase.co` was silently truncated to just
     `https:` when Xcode parsed Secrets.xcconfig.
  2. Escaping the slashes (`https:\/\/...`) does NOT fix it — verified with PlistBuddy that
     literal backslash characters end up in the actual string value, which would produce a
     broken URL (URL(string:) would fail or misparse it).
  3. Separately (and independently), Xcode's synthetic INFOPLIST_KEY_* → Info.plist generation
     mechanism (GENERATE_INFOPLIST_FILE = YES) was not honoring ANY custom keys in this Xcode
     version — confirmed even a trivial literal string key (NSHumanReadableDescription) never
     made it into the built Info.plist.

Fix applied:
  - Secrets.xcconfig now stores just the bare project ref (SUPABASE_PROJECT_REF =
    mimqecwisgzpdbeygcyj) — no slashes/colons at all, sidestepping the comment-parsing trap
    entirely.
  - Added a REAL physical Info.plist file (Book Marker/Info.plist) with all standard bundle
    keys (CFBundleIdentifier, CFBundleExecutable, etc. — normally auto-injected by the
    synthetic mechanism, had to be added explicitly once GENERATE_INFOPLIST_FILE was set to
    NO) plus SupabaseProjectRef / SupabaseAnonKey placeholders substituted via
    INFOPLIST_FILE = "Book Marker/Info.plist".
  - Config.swift rewritten to read SupabaseProjectRef and construct the full URL in Swift:
    URL(string: "https://\(ref).supabase.co"). projectURL is now typed as URL (not String).
  - AuthManager.swift updated accordingly (no more force-unwrapped URL(string:) call needed).

Verification: rebuilt clean, inspected the actual bytes in the built Info.plist via PlistBuddy
(CFBundleIdentifier, SupabaseProjectRef, SupabaseAnonKey all correct, no escaping artifacts),
then installed and launched the app in an iOS Simulator via `xcrun simctl` (had to work around
this environment's Bash-tool sandbox blocking simctl IPC — used dangerouslyDisableSandbox for
simctl install/launch/boot only) — app launched and stayed alive with no crash and no crash
report on disk.

PART 4 — SECURITY HARDENING + BOOK PROVIDER ARCHITECTURE (large multi-part task)
===================================================================================
User provided an extensive (25-section) specification covering: Supabase key-model security,

4.1 — Compromised-key incident response
  Searched the entire repo, full git history (both commits: "Created the Base" and "Added a
  login feature, and implemented the backend"), and build artifacts for any service_role/
  secret key value. Found NONE — the values that appeared in the chat transcript were
  Supabase's own dashboard-truncated/redacted display strings (never a complete usable key),
  and the one local file that ever referenced a secret key (.env) was untracked and had
  already been deleted in an earlier part of this session. Conclusion documented in
  SECURITY.md: treat any credential that passed through a chat as burned regardless, and gave
  exact dashboard rotation steps (Project Settings → API Keys → Secret keys → rotate/revoke)
  without ever asking for or reproducing the key itself.

4.2 — Database security (supabase/migrations/)
  0001_enable_rls_and_ownership_policies.sql
    - Ensures user_id on books/quotes/vocab_words defaults to auth.uid() and has a NOT NULL
      FK to auth.users(id) ON DELETE CASCADE.
    - ENABLE + FORCE ROW LEVEL SECURITY on all three tables.
    - SELECT/INSERT/UPDATE/DELETE policies requiring auth.uid() = user_id, with WITH CHECK on
      INSERT and UPDATE (blocks both inserting-as-another-user and reassigning an owned row's
      user_id to someone else — USING alone would not catch the reassignment case).
    - No anon policy anywhere → default-deny for unauthenticated requests once RLS is forced.
  0002_book_association_and_cover_url.sql
    - Additive columns: books.cover_url; quotes/vocab_words.book_id (FK to books.id, ON
      DELETE SET NULL), page_number (CHECK > 0), note (CHECK length <= 2000).
    - Indexes on the new book_id columns.
  0003_least_privilege_grants.sql
    - Explicitly REVOKEs all default/anon/PUBLIC grants on the three tables, then GRANTs
      `authenticated` only SELECT/INSERT/UPDATE/DELETE (not ownership/TRUNCATE/etc).
    - ALTER DEFAULT PRIVILEGES so future tables don't inherit a permissive anon grant.
    - Documents that no custom RPC/database functions exist in this schema today, and a
      checklist to apply if one is ever added.
  supabase/tests/rls_tests.sql
    - Manual, runnable-via-psql RLS verification script (wrapped in BEGIN/ROLLBACK, never
      commits). Seven checks: user A reads own quote (pass); user B cannot read/update/delete
      user A's quote (denied); user B cannot insert a quote owned by user A (denied); user A
      cannot reassign their own quote's user_id to user B (denied); anonymous role cannot read
      a private quote (denied).

  IMPORTANT CAVEAT (told to user explicitly): these migrations were WRITTEN but NOT applied
  to the live Supabase database — no DB/CLI credentials were available in this session. The
  user must run `supabase db push` (or paste the SQL into the Supabase SQL Editor) before the
  database is actually protected by these policies.

4.3 — Supabase Edge Functions (supabase/functions/)
  Built using the @supabase/server package (per the project's own bundled
  .agents/skills/supabase-server/SKILL.md, which was read and followed — auth: 'user' mode,
  which authenticates the caller's JWT automatically and handles CORS, before the handler
  body ever runs).
    - search-google-books/index.ts — proxies Google Books' volumes search; holds
      GOOGLE_BOOKS_API_KEY server-side only; validates query length; never forwards Google's
      raw error bodies (could echo the key back); fixed upstream host, not a generic proxy.
    - search-europeana/index.ts — same pattern for Europeana's record search API, holding
      EUROPEANA_API_KEY.
    - delete-account/index.ts — was already being called by AuthManager.swift
      (client.functions.invoke("delete-account")) but had never actually been implemented
      anywhere in the repo. Implemented now: deletes ONLY the calling user's own account
      (resolved via ctx.supabase.auth.getUser(), never a client-supplied id) using
      ctx.supabaseAdmin.auth.admin.deleteUser(...); cascades to that user's books/quotes/
      vocab_words via the ON DELETE CASCADE FK from migration 0001.
  supabase/config.toml — minimal CLI project config; verify_jwt left at its default (true)
  since all three functions use auth: 'user'.

  IMPORTANT CAVEAT: none of these functions were actually deployed (no Supabase CLI session
  available). Exact deploy commands given in SECRETS_SETUP.md.

4.4 — Book provider architecture (Swift — compiles clean, verified via xcodebuild)
  New files under Book Marker/Services/BookProviders/:
    - BookSearchModels.swift — BookProviderID enum (openLibrary, googleBooks,
      internetArchive, gutendex, libraryOfCongress, europeana, hathiTrust);
      ContentAvailability enum (fullTextAvailable / previewOnly / metadataOnly /
      userProvidedText / ocrCaptured / unavailable); RightsInformation; the provider-agnostic
      BookSearchResult struct (title, subtitle, authors, isbn10/13, publisher,
      publicationDate, edition, language, coverImageURL, provider, providerID, availability,
      fullTextAvailable, previewAvailable, searchableInside, textSource, rightsInformation)
      with back-compat convenience accessors (author, firstPublishYear, olid) so existing UI
      code kept working with minimal changes.
    - BookProvider.swift — the protocol (searchBooks, findBook(isbn:), bookDetails,
      searchInsideBook, fullText) with a protocol-extension default ("unsupported, returns
      nil/empty") so each concrete provider only implements what it actually supports.
    - EdgeFunctionClient.swift — shared helper that authenticates to this app's own Edge
      Functions using the current Supabase session's access token + the publishable anon key;
      returns nil (not a hard error) when there's no signed-in user, so a key-gated provider
      degrades gracefully instead of crashing search.
    - Concrete providers:
        OpenLibraryService.swift (existing file, extended) — now conforms to BookProvider;
          added ISBN lookup via Open Library's "Books API"; added a best-effort, honestly
          "experimental" Search Inside implementation (Open Library's own docs mark it
          experimental) that correctly discovers the per-item archive.org host via a
          /metadata/{id} lookup first, rather than hardcoding a wrong subdomain; added a
          descriptive User-Agent per Open Library's usage guidelines.
        GutendexProvider.swift — Project Gutenberg via Gutendex; the ONE provider allowed to
          assert fullTextAvailable directly from search results, since Gutenberg only ever
          hosts public-domain works.
        InternetArchiveProvider.swift — search always defaults to metadataOnly; only
          bookDetails(providerID:) (a second, explicit metadata fetch checking
          access-restricted-item and whether a real _djvu.txt OCR file is listed) is ever
          allowed to upgrade a result to fullTextAvailable — deliberately conservative per the
          copyright-safety requirement.
        LibraryOfCongressProvider.swift — metadata-only, keyless.
        HathiTrustProvider.swift — verified via live web search that HathiTrust's
          Bibliographic API is free and keyless (contrary to the task's assumption that it
          might need credentials); implements ISBN lookup against it; explicitly does NOT
          implement full-text access, since that requires HathiTrust's separate, institutional
          Data API which is out of scope.
        GoogleBooksProvider.swift / EuropeanaProvider.swift — call this app's own Edge
          Functions (never the third-party API directly), decode a normalized DTO the Edge
          Function returns.
    - BookSearchCoordinator.swift — an actor that fans a search out to all providers
      CONCURRENTLY (TaskGroup, not sequential-with-fallback), swallows individual provider
      errors so one failing provider never blocks the others, then deduplicates results
      (ISBN-13 > ISBN-10 > normalized title+author, in that preference order) and picks the
      "best" representative per group (prefers confirmed full text, then a cover image, then
      richer metadata, then a fixed provider-priority order).

  Existing UI wired to the new architecture with minimal, targeted edits:
    - CoverImageView.swift — generalized from an Open-Library-only coverID: Int? parameter to
      accept any imageURL: URL?, with a coverID-based convenience initializer kept for source
      compatibility.
    - SearchView.swift / SpotlightSearchOverlay.swift — now call
      BookSearchCoordinator.shared.searchAll(query:) instead of
      OpenLibraryService.shared.search(query:) directly (one-line swap each).
    - BookDetailSheet.swift — saveBook() now stores either the legacy numeric Open Library
      coverID (kept for its nicer resizable-image variants) or a generic coverURLString for
      every other provider.
    - Book.swift — added coverURLString: String? (additive; existing coverID field and all
      already-synced remote data untouched).
    - CoverImageCache.swift — prefers coverURLString when present, falls back to the legacy
      numeric-coverID Open Library path otherwise.

4.5 — Data model: associate quotes/words with a specific book, page numbers, notes
    - Quote.swift / VocabWord.swift — added bookID: UUID?, pageNumber: Int?, note: String?
      (all optional, additive, default nil — SwiftData migrates this automatically in DEBUG
      per the existing pattern already documented in BookMarkerApp.swift).
    - AddQuoteView.swift — saveQuote() now passes bookID: book.id (a real, concrete
      association win, since the book is already selected in that flow) — NOTE: no UI was
      built for entering page number or note; those fields exist and sync but aren't yet
      editable from the app. Flagged explicitly to the user as deferred, not forgotten.
    - SyncManager.swift — RemoteBook gained cover_url; RemoteQuote/RemoteVocabWord gained
      book_id/page_number/note. Because the local Quote/VocabWord.bookID stores the LOCAL
      SwiftData Book.id but the remote FK must reference the REMOTE books.id
      (Book.remoteID), syncUp() resolves/assigns a remoteID for the linked book on demand
      (assigning one and marking it needsSync if it didn't have one yet), and syncDown()
      builds a remote-book-id -> local-book-id map from the already-fetched remoteBooks array
      to translate the FK back when reconstructing local Quote/VocabWord instances.
